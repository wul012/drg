# 医保DRG智能协同平台 功能与完成度分析

## 1. 文档目的

本文档用于系统性描述“医保DRG智能协同平台”当前的功能覆盖范围、实现深度、完成度，以及两轮增强后的工程质量状态。它既可以作为项目交付时的自检清单，也可以作为答辩时回答“完成度”类问题的参考材料。

## 2. 项目总览

- 技术栈：Flask 3.0.3 + SQLite + Jinja2 + 本地 CSS / JS
- 核心代码：app.py，单文件组织，约 1800 行
- 模板：templates/ 下共 18 个 HTML 模板
- 样式：static/css/style.css
- 脚本：run_server.py 启动本地服务
- 数据库：instance/drg_platform.db，包含 10 张业务表
- 本地产物：
  - instance/virtual_docs/ 下为系统生成的真实文档
  - instance/submissions/ 下为系统生成的提交清单
- 测试：
  - tests/test_drg_rules.py：15 条纯函数单元测试
  - tests/test_case_helpers.py：9 条病例筛选、排序、分页和分布辅助函数测试
  - tests/test_drg_json_examples.py：2 条 JSON 样例驱动测试
  - tests/test_local_llm.py：5 条本地微型LLM专项测试
  - smoke_test.py：集成级关键业务路径冒烟测试
- 文档：
  - README.md
  - docs/演示过程说明.md
  - docs/答辩讲稿.md
  - docs/功能与完成度分析.md（本文件）

## 4. 数据库结构

项目数据库共 10 张表，且包含自动迁移逻辑，可以在老库上平滑升级。

- users：用户、角色、密码哈希
- projects：项目主信息
- analyses：需求分析产出
- drg_cases：病例、诊断、手术、入组结果、解释
- agents：Agent 角色和当前状态
- messages：桌面端与移动端消息流
- documents：文档元信息、内容、源 Agent、本地存储路径
- test_cases：测试用例（包含类别：正常 / 边界 / 异常）
- submissions：提交批次、提交清单路径
- mobile_reports：移动端上报

迁移逻辑由 run_schema_migrations 负责，使用 ensure_column_exists 增量追加缺失列，不会破坏已有数据。

## 5. 本地教学版 DRG 规则

当前规则覆盖 8 个教学版 MDC 大类，并额外支持截图 JSON 样例中的编码版与无编码版病例。

| MDC | 名称 | 示例诊断前缀 | 对应 ADRG |
|---|---|---|---|
| MDCB | 神经系统 | G01, I60, I61, I63, A01.002 | BB1 / BZ1 |
| MDCA | 呼吸系统 | J18, J44, J96, J12 | AB1 / AZ1 |
| MDCD | 消化系统 | K35, K36, K80, K81 | GD1 / GZ1 |
| MDCG | 消化道疾病及功能障碍 | C16 | GB2 / GZ2 |
| MDCH | 肝胆胰疾病及功能障碍 | K83 | HC1 / HZ1 |
| MDCF | 内分泌代谢 | E10, E11, E14, L97 | KD1 / KZ1 |
| MDCE | 循环系统 + 样例呼吸特例 | I20, I21, I25, I50, J86.000x013 | EC2 / FB1 / FZ1 |
| MDCL | 泌尿系统 | N17, N18, N20, N39 | LB1 / LZ1 |

并发症层级判断使用 SIMPLIFIED_MCC_CODES 和 SIMPLIFIED_CC_CODES 两个集合，未命中主诊断大类时会回退到 MDCQ / QZ1 并标记“需复核”，具备完整的可解释性。

## 6. 增强清单

### 6.3 第三轮增强

1. 新增纯 Python 本地微型LLM模块 `local_llm.py`，不依赖任何外部 API
2. 将本地微型LLM接入 DRG 入组原因说明，并作为病例页主要展示点
3. 将本地微型LLM复用到需求分析、文档正文和测试用例文案生成
4. 新增 `local_llm_corpus.json` 外部语料文件，可直接扩充四类生成语料
5. 在需求分析页增加 `严谨模式 / 平衡模式 / 增强模式` 三档模式切换，并联动刷新下游内容
6. 在分析页、文档页、测试页和病例页增加“本地微型LLM”模式标识
7. 新增 `tests/test_local_llm.py`，并扩展 smoke_test.py 覆盖模式切换与页面标识

### 6.4 JSON 样例测试增强

1. 支持 `drg_example(1).json` 中胃、十二指肠大手术、纵隔/气管/胸壁手术、胆总管手术三类样例
2. 支持 `drg_example_nocode(1).json` 中基于诊断名称和手术名称的自动补码
3. 新增 `tests/test_drg_json_examples.py`，对编码版和无编码版 JSON 样例执行分组断言

## 7. 自动化测试一览

### 7.1 单元测试（tests/test_drg_rules.py）

15 条用例，零第三方依赖，直接使用 assert：

- match_mdc 已知 4 条 + 回退 1 条
- match_adrg 命中 + 回退到内科组 + 未知 MDC 共 3 条
- detect_complication_level MCC / CC / 无 共 3 条
- group_drg_case 神经 + MCC / 循环 + CC / 泌尿 + 无 / 未知需复核 共 4 条
- 规则目录完整性 1 条

运行命令：

```bash
python tests/test_drg_rules.py
```

### 7.2 本地微型LLM测试（tests/test_local_llm.py）

5 条用例，覆盖以下能力：

- DRG 原因说明保留核心编码事实

- 文档正文能够引用最新病例上下文
- 测试用例维持 4 条稳定结构
- 模式规范化、模式标签和外部语料文件加载元信息

运行命令：


### 7.3 病例辅助函数测试（tests/test_case_helpers.py）

- 分页页码越界时自动收敛
- 分布统计的兜底标签、百分比和样式映射

运行命令：

### 7.5 冒烟测试（smoke_test.py）

当前覆盖的关键路径包括：

- 首页访问

- 注册校验失败
- 注册成功
- 登录成功
- 需求分析字段超长校验
- 需求分析成功 + 增强模式切换 + 级联刷新
- DRG 入组字段缺失校验
- DRG 入组成功
- 循环系统 MDCE 入组成功
- 病例筛选命中
- 病例筛选无结果
- 文档下载成功（Content-Disposition attachment）
- 文档下载不存在 404
- 管理员删除成功
- 管理员提交成功
- 分析员越权删除被拒
- 移动端上报字段校验
- 移动端上报成功 + 消息同步

运行命令：

```bash
python smoke_test.py
```

### 7.6 新增测试用例验收要求

后续新增测试用例应满足以下标准：

- 不依赖外部 API、网络服务或真实生产数据库
- 单元测试优先覆盖纯函数，输入输出明确，失败时能直接定位到函数行为
- DRG 相关测试必须断言核心业务事实，例如 MDC、ADRG、DRG、并发症层级、状态和风险等级
- 本地微型LLM相关测试必须保证结构稳定，并保留核心编码事实，避免只断言随机文案
- 页面或流程级测试应至少覆盖状态码、关键页面文本、权限边界和数据变化结果
- 所有测试必须能通过 `python tests/test_drg_rules.py`、`python tests/test_case_helpers.py`、`python tests/test_drg_json_examples.py`、`python tests/test_local_llm.py` 和 `python smoke_test.py` 独立运行
- 测试数据应使用临时库或内存构造，不能污染 `instance/drg_platform.db`

## 8. 可选的后续增强方向

以下方向对课程完成度无硬性要求，但如果要继续打磨，可以考虑：

- 病例编辑：允许管理员或录入人员修改已有病例的主诊断、次诊断或手术编码
- 文档版本历史：保留文档的历史版本而不是只保留最新
- 多项目支持：当前 get_project() 默认取第一条，可改为项目列表 + 切换
- 部署打包：增加 Dockerfile 或 Waitress/Gunicorn 生产启动脚本
- 批量导入病例：支持 CSV 导入，方便构造更大规模的分布演示
- DRG 规则继续扩展：增加骨肌系统、肿瘤系统等更多大类

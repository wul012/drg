# 医保DRG智能协同平台页面操作指南

## 1. 适用对象

本文档给第一次使用本项目的同学、老师或验收人员使用。  
目标是帮助用户从 GitHub 克隆项目后，知道如何启动系统、登录系统，以及每个页面应该怎么点、填什么、看到什么结果。

项目定位是课程设计演示系统，核心演示路线是：

```text
首页 -> 登录 -> 工作台 -> 需求分析 -> DRG分析 -> Agent协作 -> 文档中心 -> 测试用例 -> 提交中心 -> 移动端
```

## 2. 启动项目

从 GitHub 克隆后，在命令行执行：

```powershell
git clone https://github.com/wul012/drg.git
cd drg/drg-ui-prototype
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run_server.py
```

启动成功后，浏览器会打开：

```text
http://127.0.0.1:5000
```

如果浏览器没有自动打开，手动复制上面的地址访问即可。

## 3. 默认账号

建议首次演示使用管理员账号：

| 用户名 | 密码 | 角色 | 适合用途 |
|---|---|---|---|
| admin | 123456 | 管理员 | 完整演示全部功能，包括撤销病例 |
| doctor | 123456 | 医生 | 查看和录入业务数据 |
| analyst | 123456 | 分析员 | 查看分析结果，不能撤销病例 |

注意：只有管理员可以在 DRG 病例列表中点击“撤销该病例”。

## 4. 推荐演示路线

### 4.1 首页

访问 `http://127.0.0.1:5000` 后会进入项目首页。

可以看到：

- 项目名称：医保DRG智能协同平台
- 入口按钮：登录系统、注册账号
- 项目能力概览
- 桌面端和移动端入口

首次使用建议点击“登录系统”。

### 4.2 登录页面

进入登录页后填写：

```text
用户名：admin
密码：123456
```

点击“登录并进入系统”。

登录成功后会进入“工作台首页”。

### 4.3 工作台首页

工作台首页用于快速观察项目当前状态。

主要看三块内容：

- 项目快照：文档、测试、病例、提交等数量
- DRG 入组分布：按 MDC、风险等级、状态显示条形图
- 最近任务时间线和最近消息

如果不知道下一步点哪里，点击“推进主流程”，会进入需求分析页面。

### 4.4 需求分析页面

页面名称为“项目需求分析”。

这里用于录入课程项目的需求背景，并触发后续 Agent、文档、测试用例同步刷新。

推荐填写示例：

```text
项目名称：医保DRG智能协同平台-演示版

需求描述：
围绕住院病例信息、DRG规则匹配、多Agent协作、文档生成和提交流转展开，
实现一个可运行、可演示、可验证的课程设计系统。

目标产物：
完成需求分析、DRG入组、文档生成、测试用例生成和提交留痕闭环。

优先级：高
文档类型：完整提交包
本地微型LLM模式：增强模式
```

填写完成后点击：

```text
开始分析并同步数据
```

预期结果：

- 页面出现“需求分析已完成”提示
- 分析结果区刷新
- 文档中心内容刷新
- 测试用例内容刷新
- Agent 消息流同步更新

下一步点击“进入 Agent 协作”，或从左侧导航进入“DRG分析”。

### 4.5 DRG分析页面

页面名称为“DRG规则匹配与病例分析”。

这里是项目的核心演示页面，用于录入病例并执行教学版 DRG 入组。

推荐病例一：神经系统高风险病例

```text
患者姓名：张三

电子病历摘要：
患者主诊断 A01.002+G01，次诊断 J96.0，主要手术 38.1000X002。

主诊断编码：A01.002+G01
主诊断名称：伤寒性脑膜炎
次诊断编码列表：J96.0
主手术编码：38.1000X002
主手术名称：动脉内膜剥脱术
```

填写完成后点击：

```text
执行DRG入组
```

预期结果：

- 页面提示已完成本地教学规则入组
- 最新 DRG 入组输出显示 MDC、ADRG、DRG、风险等级
- 入组原因说明中出现“本地微型LLM”说明文本
- 病例列表新增一条病例
- 下游文档和测试用例同步刷新

推荐病例二：循环系统病例

```text
患者姓名：李四

电子病历摘要：
患者主诊断 I21.0 急性心肌梗死，次诊断 I10，执行冠状动脉搭桥术。

主诊断编码：I21.0
主诊断名称：急性心肌梗死
次诊断编码列表：I10
主手术编码：36.10
主手术名称：冠状动脉搭桥术
```

预期结果中应能看到：

```text
MDC：MDCE
ADRG：FB1
```

### 4.6 病例列表筛选

DRG分析页面下方有“病例列表”。

可以使用：

- MDC 大类筛选
- 风险等级筛选
- 状态筛选
- 关键词搜索
- 排序方式
- 分页按钮

示例操作：

```text
MDC：MDCE
关键词：心
```

点击“筛选”后，列表应只保留循环系统相关病例。

如果筛选条件没有命中，会显示空结果提示。点击“重置”可以恢复全部病例列表。

管理员账号可以点击“撤销该病例”。医生和分析员账号不会显示该操作，直接访问删除接口也会被后端拒绝。

### 4.7 Agent协作页面

页面名称为“多 Agent 协作监控”。

这个页面用于展示系统中多个本地 Agent 的协作状态。

主要查看：

- 需求分析 Agent
- DRG 分析 Agent
- 文档生成 Agent
- 测试用例 Agent
- 提交 Agent
- 消息流 / 通信记录

如果刚刚完成了需求分析或 DRG 入组，这里会出现对应的消息更新。

下一步点击“进入文档中心”。

### 4.8 文档中心

页面名称为“文档自动生成中心”。

左侧或上方可以看到文档列表，通常包括：

- 需求分析文档
- 架构设计文档
- 测试文档

点击任意文档后，右侧会显示：

- 文档标题
- 文档版本
- 来源智能体
- 接收时间
- 本地存储路径
- 文档正文预览

如果有“下载原文件”按钮，可以点击下载本地生成的 txt 文档。

下一步点击“进入测试中心”。

### 4.9 测试用例页面

页面名称为“测试用例中心”。

这里展示系统自动生成的测试用例，通常包含：

- 正常场景
- 边界场景
- 异常场景

可以点击“重新生成用例”，让系统基于当前项目和最新病例重新生成测试文案。

检查点：

- 用例编号是否存在
- 功能点是否和当前项目相关
- 预期结果是否包含 DRG 或本地微型LLM相关说明

下一步点击“进入提交中心”。

### 4.10 提交中心

页面名称为“虚拟文档系统提交中心”。

这里用于模拟课程项目最终提交。

操作步骤：

1. 查看“待提交文档清单”
2. 保持需要提交的文档为勾选状态
3. 点击“确认提交”

预期结果：

- 页面提示提交成功
- 文档状态更新为已提交
- 历史提交记录新增一条
- 本地生成提交清单文件

提交清单会生成在：

```text
instance/submissions/
```

## 5. 移动端页面

登录后，在桌面端右上角点击“切换到移动端”，或直接访问：

```text
http://127.0.0.1:5000/mobile/home
```

移动端底部有四个入口：

```text
首页 / 上报 / 消息 / 文档
```

### 5.1 移动端首页

用于查看项目基本状态和今日待办。

### 5.2 移动端上报

点击“上报”，填写示例：

```text
标题：新增病例录入需求
内容：需要补充住院天数、并发症描述和术后观察字段。
优先级：高
```

点击“提交上报”。

预期结果：

- 页面提示上报成功
- 移动端消息页出现新消息
- PC 端 Agent 消息流同步新增记录

### 5.3 移动端消息

用于查看移动端和 PC 端同步后的消息流。

### 5.4 移动端文档

用于查看最新文档、最近提交和移动端上报摘要。

点击页面右上角“PC端”可以返回桌面端。

## 6. 常见问题

### 6.1 提示 No module named 'drg_case_utils'

说明 GitHub 仓库里缺少运行模块，或本地代码不是最新版本。

处理方式：

```powershell
git pull
python run_server.py
```

当前版本已经把 `drg_case_utils.py` 和 `local_llm.py` 提交到仓库。

### 6.2 提示 No module named 'flask'

说明还没有安装依赖。

处理方式：

```powershell
pip install -r requirements.txt
```

### 6.3 PowerShell 不允许激活虚拟环境

如果执行 `.\venv\Scripts\Activate.ps1` 被拦截，可以临时放开当前窗口策略：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
```

也可以使用：

```powershell
venv\Scripts\activate.bat
```

### 6.4 端口 5000 被占用

关闭其他占用 5000 端口的程序，或修改 `run_server.py` 里的端口：

```python
PORT = 5001
```

然后重新运行：

```powershell
python run_server.py
```

### 6.5 没有数据库文件

这是正常现象。首次运行项目时会自动创建：

```text
instance/drg_platform.db
```

同时会初始化默认账号和演示数据。

### 6.6 页面数据被自己操作乱了

课程演示时建议重新拉取一份干净项目，或者删除本地数据库后重新启动：

```powershell
Remove-Item instance\drg_platform.db
python run_server.py
```

删除数据库会清空本地操作数据，系统会重新生成默认演示数据。

## 7. 十分钟演示建议

如果时间有限，建议按这个顺序演示：

1. 使用 `admin / 123456` 登录
2. 工作台展示项目快照和 DRG 分布
3. 需求分析页切换“增强模式”，提交一次需求分析
4. DRG分析页录入一条 `I21.0 + 36.10` 循环系统病例
5. Agent协作页查看消息流变化
6. 文档中心查看自动生成文档，并下载原文件
7. 测试用例页查看正常、边界、异常测试
8. 提交中心勾选文档并确认提交
9. 移动端上报一条新需求
10. 回到 PC 端查看消息同步

这条路线能完整展示“需求 -> 病例 -> Agent -> 文档 -> 测试 -> 提交 -> 移动端协同”的业务闭环。

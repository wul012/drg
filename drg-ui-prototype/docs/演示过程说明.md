# 医保DRG智能协同平台演示过程说明

## 1. 文档用途

本文档用于说明“医保DRG智能协同平台”课程项目的现场演示流程、关键展示点、每一步对应的系统能力，以及本次自动化演示的实际结果，便于课程汇报、答辩展示和项目归档。

## 2. 项目概述

本项目采用 Flask + SQLite 实现，围绕医保 DRG 课程实验场景，完成了桌面端工作台、需求分析、DRG 病例入组、多 Agent 协作、文档自动生成、测试用例生成、虚拟文档系统、提交中心以及移动端协同页面等功能。

本次实现采用“可运行实现 + 内置简化规则 + 本地规则/模板驱动”的方式，不依赖外部大模型或真实生产级 DRG 引擎，而是使用本地教学版规则完成完整业务闭环。

## 3. 演示目标

本次演示重点验证以下能力：

- 用户可以正常登录系统并进入桌面端工作台
- 可以录入病例并执行本地教学版 DRG 入组
- 系统可以根据需求与病例结果自动生成文档
- 系统可以根据规则自动生成正常、边界、异常三类测试用例
- 系统可以在提交中心完成文档勾选、提交批次生成和本地提交清单落盘
- Agent 协作页面可以显示系统状态与消息流同步结果

## 4. 演示环境

- 后端框架：Flask
- 数据存储：SQLite
- 前端模板：Jinja2
- 样式方案：本地 CSS
- 运行方式：本地开发服务
- 自动演示方式：Playwright 浏览器自动化

## 7. 演示时建议强调的亮点

### 7.1 可运行而非静态原型

系统所有主要数据均保存在 SQLite 中，页面会随着操作实时变化，说明它不是静态拼图页面。

### 7.2 教学版 DRG 规则可解释

本项目虽然不是生产级 DRG 引擎，但具备教学版规则匹配、可解释入组链路和风险提示，符合课程实验场景。

### 7.3 文档与测试不是硬编码展示

文档和测试用例会随着需求分析结果和病例结果更新，具备联动关系。

### 7.4 提交留痕真实存在

提交中心不仅更新数据库记录，还会真实生成本地提交清单，体现了“虚拟文档系统”的实现闭环。

## 8. 总结

本项目已经完成课程实验要求中的核心业务闭环：从需求分析、病例入组、协作生成、文档沉淀、测试覆盖到提交留痕，均可以在本地环境中完整演示。该实现方案在可运行性、可解释性、课程适配性和现场展示效果之间取得了较好的平衡，适合作为课程项目最终成果进行展示。

## 9. 功能增强版演示流程

在基础版本之上，本项目又进行了两轮增强，增强项全部已经通过自动化测试和 Playwright 现场演示验证。下面给出针对增强能力的扩展演示流程。

### 9.1 第一轮增强：规则扩展、删除与权限

本轮主要补齐三件事：

- 规则扩展：DRG 规则从 4 个 MDC 扩展到 6 个 MDC
  - 新增 MDCE 循环系统疾病大类，含 FB1 冠状动脉搭桥手术组和 FZ1 内科治疗组
  - 新增 MDCL 泌尿系统疾病大类，含 LB1 肾与尿道手术组和 LZ1 内科治疗组
- 病例撤销：管理员可以在 DRG 病例历史列表中撤销病例，撤销后会自动刷新 Agent 状态、消息流、文档和测试
- 角色权限：通过 role_required 装饰器限定只有“管理员”可以执行撤销操作，分析员和医生角色看不到撤销按钮，即使绕过前端直接 POST 也会被后端拒绝

对应的演示步骤：

1. 使用 admin 账号登录
2. 进入 DRG 分析页面，录入主诊断 I21.0、主手术 36.10 的循环系统病例，验证系统返回 MDCE → FB1 → FB13 的入组链路
3. 在历史列表中点击“撤销该病例”，弹窗确认后，页面自动刷新且删除按钮数量相应减少
4. 退出登录，使用 analyst 账号重新登录
5. 进入 DRG 分析页面，可以看到剩余病例，但所有“撤销该病例”按钮不再显示
6. 使用浏览器开发者工具直接发送 POST /cases/<id>/delete，会被后端拦截并显示“当前账号没有执行该操作的权限”的警告消息

### 9.2 第二轮增强：筛选、下载与分布可视化

本轮补齐三件事：

- 病例筛选与搜索：DRG 病例列表支持按 MDC 大类下拉筛选，并支持病例编号、患者姓名、主诊断、主手术等多字段的关键词搜索
- 虚拟文档下载：文档中心的“下载原文件”按钮会直接返回 instance/virtual_docs 下的原始文本文件，体现虚拟文档系统不是假落盘
- 仪表盘分布可视化：工作台首页新增 DRG 入组分布面板，包括 MDC 大类分布、风险等级分布和状态分布三个条形图，不依赖前端图表库

对应的演示步骤：

1. 使用 admin 账号登录
2. 进入 DRG 分析页面，先录入一条 MDCE 循环系统病例，然后使用筛选条选择 MDCE 并输入关键词“心”，页面会展示“共 N 条 · 命中 1 条”，只保留命中的病例
3. 将关键词改为任意不存在的字符串，页面立即进入空结果状态“当前筛选条件下没有命中的病例”
4. 点击“重置”清空筛选，所有病例重新出现
5. 进入文档中心，在某份文档上点击“下载原文件”，浏览器会下载一份以文档标题命名的 txt 文件，打开即可看到系统生成的真实内容
6. 回到工作台首页，在“DRG 入组分布”面板中可以看到三列条形图：MDC 大类分布、风险等级分布、状态分布，分别按占比排序

### 9.3 增强功能自动化验证

本项目在增强过程中同时补充了两类自动化测试：

- 纯函数单元测试：tests/test_drg_rules.py 共 15 条用例，覆盖 match_mdc、match_adrg、detect_complication_level、group_drg_case 四个核心函数在六类 MDC 和 CC / MCC / 无并发症三种情形下的行为
- 冒烟测试扩展：smoke_test.py 覆盖了登录、注册、需求分析、DRG 入组、循环系统 MDCE 入组、病例筛选命中、病例筛选无结果、文档下载、文档下载 404、管理员删除、分析员删除被拒、提交中心、移动端上报等 13 条关键路径

运行方式：

```bash
python tests/test_drg_rules.py
python smoke_test.py
```

两条命令都会在本地直接执行完毕，无需第三方测试框架依赖。

## 11. 第三轮增强：本地微型LLM、模式切换与全链路验证

在前两轮增强之后，项目又补上了第三轮更偏“本地智能生成 + 工程化配置”的增强，重点包含以下三件事：

- 新增 `local_llm.py`，实现纯 Python、本地可运行的微型LLM，不依赖任何外部 API
- 新增 `local_llm_corpus.json`，把四类生成语料落到外部文件，便于后续直接扩充
- 在需求分析页增加 `严谨模式 / 平衡模式 / 增强模式` 三档模式切换，并让 DRG 原因说明、文档正文和测试用例联动刷新

对应的现场演示步骤可以这样讲：

1. 进入需求分析页，顶部会显示“本地微型LLM · 当前模式”标识
2. 将模式切换到“增强模式”并重新提交需求分析，系统会立刻刷新分析结果、文档和测试用例
3. 进入 DRG 分析页录入一条循环系统病例，观察“入组原因说明”区域显示“本地微型LLM · 增强模式”标签，并输出更自然的解释文本
4. 进入文档中心，查看文档头部和详情元信息中的模式标识，同时确认正文已写入“生成策略”说明
5. 进入测试中心，确认顶部出现模式标识，并且测试用例文案已经带有增强模式下的表达特征
6. 进入提交中心执行一次真实提交，确认新提交批次和本地提交清单文件继续正常生成
